# CARMA — rules for Claude Code

CARMA builds an architecture map of a C++ codebase from indexed facts and an editable model, and answers questions about the code through an agent that highlights routes on the map.

- The spec is the source of truth: `docs/carma-spec.md` (Russian). When code and spec disagree, fix the spec first, then the code.
- Background and the reasoning behind decisions: `docs/carma-conversation.md`.
- `docs/` is kept out of git for now (excluded in `.git/info/exclude`): it exists only in the author's working copy.
- Milestones and their acceptance criteria: spec, «Этапы реализации». Current: M1 (facts) implemented; waiting for CI on macOS/Linux and the author's check of five «who calls» answers; M2 next.

## Commands

```
uv sync                   # install dependencies (uv installs Python 3.12 itself)
uv run pytest             # all tests; those needing LLVM or CMake skip without them
uv run pytest -m "not e2e"  # skip end-to-end tests
uv run carma index --project gd-engine          # index the test codebase
uv run python scripts/regen_golden_facts.py    # after changing the fixture or the adapter
```

Set `CARMA_REQUIRE_LIBCLANG=1` to make missing LLVM or CMake a failure instead of a skip (CI does).
Libclang is found through `CARMA_LIBCLANG`, `LLVM_PATH`, `llvm-config` or standard install paths.

## Indexer notes

- Canonical ID rules live in the spec («Канонические идентификаторы»); `carma/indexers/libclang/walker.py` implements them. Any rule change needs a case in `fixtures/golden_cpp` and an entry in `expected/`.
- Output must not depend on the number of worker processes; a contract test compares 1 and 3 workers.
- Workers start with `spawn`: scripts that call `index_project(..., jobs>1)` need an `if __name__ == "__main__":` guard.

## Rules

1. A contract change goes in one piece: schema, version number, contract tests, then the implementation.
2. SQL appears only in `carma/store/sqlite/`.
3. `carma/engine/` has no LLM calls and no network access.
4. The UI and the MCP server talk only to the View API.
5. Every task ends with green `tests/contract` and `tests/unit` on Windows, macOS and Linux.
6. A new dependency needs a reason in the change description and native builds for all three OSes.
7. Paths go through `pathlib`; in facts, the model and the API they are relative and use `/`. On Windows, compare paths case-insensitively. Run external commands with an argument list, never a shell string.

## Test data

- `fixtures/golden_cpp/` — reference project; `expected/` is written by hand, never generated by an adapter.
- `gd-engine/` — snapshot of the author's engine, the real codebase for M1–M5. Not in git. Its vendored libraries in `engine/thirdparty/` are not indexed while testing.

## Working agreements

- The author commits. Do not run `git commit` or `git push`; report what is ready to commit instead.
- Code, comments and docstrings in English; the spec and conversation with the author in Russian.
